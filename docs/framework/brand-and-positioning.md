# Brand and positioning

- **Name:** CraftRail (owner-selected working name)
- **Tagline:** Guardrails for agent-driven development.
- **Description:** A Git-native, agent-neutral framework for keeping engineering intent, architecture, and verification aligned across human and AI-assisted development.
- **Audiences:** Individual engineers using coding agents, staff/principal engineers, technical leads, and small engineering teams.
- **Pains:** Context loss, undocumented assumptions, requirements drift, inconsistent agent instructions, decisions lost in chat, and weak traceability from intent to tests.
- **Demonstrable promises:** Reusable project structure, templates, shared agent guidance, requirement IDs, traceability examples, and lightweight validation.
- **Non-promises:** No guarantee of agent correctness; no replacement for tests, code review, engineering judgment, or a team's existing delivery method; no required agent, language, or architecture.
- **Adoption:** Use as a GitHub template, copy selected conventions into an existing repo, or adopt gradually alongside current tools.

## Differentiation and coexistence

CraftRail assembles durable project-level intent, requirements, architecture/ADRs, contracts, verification, and small offline checks. Teams can use Spec Kit or OpenSpec for more automated feature workflows while retaining CraftRail-owned long-lived requirements and architecture. Decide which artifact is canonical, then link to it. Avoid maintaining parallel feature specs. See the [fact-checked comparison](ecosystem-comparison.md).
